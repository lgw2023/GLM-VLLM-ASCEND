## 8. NPU keep-alive 与占卡规则

服务器默认运行低优先级 NPU keep-alive 工作负载。所有当前和未来的 NPU 任务必须遵守：

1. 只停止任务实际需要的卡，不得顺手停止其他卡。
2. 不使用 NPU 的任务必须保持 keep-alive 运行。
3. NPU 任务无论成功、失败、中断还是提前退出，都必须恢复同一组卡。
4. 结果报告必须写明 `stopped_card_ids`、`restored_card_ids` 和 `restoration_status`。
5. 卡号应在任务合同中显式给出，命令末尾的数字必须收窄到实际卡集。

示例（仅表示命令形式，不代表本项目自动获准使用 8 卡）：

```bash
# 停止选定卡上的低优先级 keep-alive。
bash /data/node0_disk1/Public/npu_stop.sh 0 1 2 3 4 5 6 7

# 在所有退出路径恢复完全相同的卡集。
bash /data/node0_disk1/Public/npu_keep_alive.sh 0 1 2 3 4 5 6 7
```

每次启动模型前还必须检查：

```bash
npu-smi info
```

历史“某卡空闲”不构成当前占卡授权。卡健康、空闲、无冲突进程和用户授权必须在同一任务轮重新闭合。

当前 keep-alive 的机器判据是：恢复后共有 16 个 marker，精确覆盖 `#0#` 到 `#7#`，且相关 process group 完全属于官方 keep-alive。

只读脚本身份检查：

```bash
sha256sum \
  /data/node0_disk1/Public/npu_stop.sh \
  /data/node0_disk1/Public/npu_keep_alive.sh
```

下面的脱敏快照输出 marker 进程及其 PGID 的全部成员；每行只包含 PID、PGID、可执行文件、marker 和完整命令行哈希，不输出可能含参数的完整命令行。分别在操作前、停止后、恢复后保存为三个 JSON 文件：

```bash
python3 - <<'PY'
import hashlib
import json
import os
from pathlib import Path

markers = [f"#{i}#" for i in range(8)]
all_rows = []
for entry in Path("/proc").iterdir():
    if not entry.name.isdigit():
        continue
    pid = int(entry.name)
    try:
        raw = (entry / "cmdline").read_bytes()
        command = raw.replace(b"\0", b" ").decode("utf-8", errors="replace")
        hits = [marker for marker in markers if marker in command]
        all_rows.append(
            {
                "pid": pid,
                "pgid": os.getpgid(pid),
                "exe": os.readlink(entry / "exe"),
                "markers": hits,
                "cmdline_sha256": hashlib.sha256(raw).hexdigest(),
            }
        )
    except (FileNotFoundError, PermissionError, ProcessLookupError):
        continue

marker_rows = [row for row in all_rows if row["markers"]]
marker_pgids = {row["pgid"] for row in marker_rows}
pgid_members = [row for row in all_rows if row["pgid"] in marker_pgids]
counts = {marker: 0 for marker in markers}
for row in marker_rows:
    for marker in row["markers"]:
        counts[marker] += 1
print(
    json.dumps(
        {
            "marker_process_count": len(marker_rows),
            "marker_counts": counts,
            "marker_processes": marker_rows,
            "marker_pgid_members": pgid_members,
        },
        ensure_ascii=False,
        indent=2,
    )
)
PY
```

当前合同的通过条件：操作前和恢复后的每卡 marker 数完全相同、总 marker 数为 16、8 个 marker 均存在；停止后，选定卡的 marker 消失，未选卡的规范化进程签名不变；恢复后，选定卡也必须恢复到操作前的规范化进程签名；三个阶段的卡均健康，且没有非 keep-alive 业务进程被终止。规范化签名至少包含 marker、可执行路径、命令行 SHA-256，以及 marker 所在 PGID 的全部成员身份，比较时只忽略预期变化的 PID/PGID 数值。若实际官方脚本采用了新 marker 形态，应先由服务器管理员提供新的机器判据，不能放宽为“看起来有进程”。

## 8. 代码同步与服务器本地改动

### 9.1 权限模型

- 远程 `origin/main` 只由外部开发者维护。
- 服务器任何分支都禁止 push。
- 服务器主镜像工作区只允许 fetch/pull 和只读执行；tracked 文件不得在服务器上直接修改。
- 服务器过程证据和结果应写到 Git 忽略的 `server_local/<task_id>/` 或任务明确指定的结果目录。
- 只有确需真实服务器适配的代码才进入独立 server-local worktree，并形成服务器本地 commit；不得合并回主镜像 `main`。
- 是否把服务器本地实现带回外部仓库，由外部开发者审核决定。
