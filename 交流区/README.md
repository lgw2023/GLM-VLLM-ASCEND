# 三人文档交流区

这里是 liguowei、qinyingqi、yangyinyue 共用的唯一交流入口，直接位于项目根目录，与三个个人工作目录并列。

## 目录

- `liguowei/`：liguowei 发起的信息、需求和交接。
- `qinyingqi/`：qinyingqi 发起的信息、需求和交接。
- `yangyinyue/`：yangyinyue 发起的信息、需求和交接。

发起人只在自己的空间创建文件；接收人将回复和处理状态补充到同一文件中。这样可以明确文件归属，减少同时创建或修改同名文件的冲突。

一条事项使用一个 Markdown 文件，文件名采用：

```text
YYYYMMDD-HHMM-发送人-to-接收人-简短主题.md
```

接收人为全体时写 `all`。同一事项的回复和状态更新写回原文件，不重复新建总结。

## 内容格式

```markdown
# 标题

- 类型：需求 / 交接 / 决策
- 发起人：
- 接收人：
- 创建时间：YYYY-MM-DD HH:MM
- 状态：待处理 / 处理中 / 待确认 / 已完成
- 涉及仓库：vllm / vllm-ascend / 文档
- 分支或 commit：

## 内容

说明背景、目标、边界和验收条件。

## 回复与结果

由接收人补充处理结论、验证证据和后续事项。
```

## 协作边界

- 个人方案、脚本、实验记录和待合入成果放在项目根目录各自的 `<姓名>/` 中；交流信息放在根目录 `交流区/<姓名>/` 中。
- 公共代码只走同一个 `main` 主分支；传递代码时记录涉及文件和 commit ID，不在交流区复制源码。
- 需要三人共同遵守的结论由发起人记录在自己的交流空间，并将接收人写为 `all`。
- 不在交流区写密码、私钥、Token 或其他认证信息。
